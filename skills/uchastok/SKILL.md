# UCHASTOK

Используй MCP-сервер `uchastok`. Его инструменты в Hermes имеют префикс
`mcp_uchastok_`.

## Запрос по кадастровому номеру

1. Проверь номер по формату `AA:BB:CCCCCC(C):DD...`: четыре цифровых сегмента,
   разделённых двоеточиями. Не удаляй ведущие нули и не меняй ширину сегментов.
2. Для обычной оценки вызови `mcp_uchastok_parcel_profile` с
   `depth="standard"` и `include_environment=true`.
3. Если пользователь просит исчерпывающую, полную или максимально подробную
   информацию, используй `depth="full"` и `include_environment=true`.
4. Сначала прочитай `summary`, затем обязательно проверь структурированные блоки
   `parcel`, `restrictions`, `environment`, `risks`, `score` и `meta`.
5. Если нужен полный перечень зон или дополнительная проверка ограничений, вызови
   `mcp_uchastok_parcel_restrictions`. Чтобы выбрать конкретные слои, сначала
   получи их коды через `mcp_uchastok_list_layers`.
6. Для объяснения сработавшего риска вызови `mcp_uchastok_explain_rules` с кодом
   фактора.
7. Когда пользователь просит точные площади пересечения участка со всеми ЗОУИТ,
   используй `analyze_zouit_intersections`. Инструмент получает геометрии через
   REST и независимо пересчитывает пересечения с помощью Shapely.
8. Для социальной инфраструктуры в окружности участка используй
   `analyze_social_infrastructure`. Инструмент строит минимальную описывающую
   окружность участка, добавляет к радиусу 1000 метров и возвращает кратчайшее
   расстояние до участка. Для объектов вне целевой окружности выводится `∞`.

## Как отвечать

Структурируй ответ по разделам:

- идентификация, адрес и статус границ;
- площадь, категория, ВРИ, стоимость, здания и части участка;
- зоны, ограничения, негативные процессы и свободная доля площади;
- окружение, транспорт, социальные объекты и инженерные сети;
- рельеф, население, ветер и спутниковые признаки, если они собраны;
- риски по убыванию серьёзности;
- итоговый балл вместе с `score.confidence`;
- полнота и дата данных.

Всегда соблюдай следующие правила:

- Не называй данные НСПД выпиской из ЕГРН и укажи, что они не имеют юридической
  силы.
- Пустой блок не означает отсутствие ограничений. Проверь `meta.partial` и
  `meta.missing_blocks`; явно перечисли всё, что не было собрано.
- Не трактуй `score.total` без `score.confidence`.
- Отделяй факты из ответа сервера от выводов и рекомендаций.
- Не скрывай предупреждения, ошибки источников и низкую полноту данных.
- Повторяй запрос только для `upstream_unavailable`, `all_proxies_blocked` и
  `upstream_error`, соблюдая задержку не менее минуты. Другие ошибки не лечатся
  повтором.

## Другие сценарии

- Только координаты: `mcp_uchastok_resolve_point`, затем профиль выбранного
  пользователем участка. При `ambiguous=true` не выбирай кандидата сам.
- Собственный Polygon/MultiPolygon EPSG:4326:
  `mcp_uchastok_analyze_environment`.
- Проверка одного ограничения: `list_layers` → `parcel_restrictions` с выбранными
  кодами слоёв.
